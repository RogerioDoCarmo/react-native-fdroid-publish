react-native-fdroid-publish

An agent skill that takes a React Native or Expo Android app all the way onto F-Droid.

Source on GitHub Install Releases

What it does

Audits what F-Droid would reject, builds an F-Droid variant, patches Google libraries out of Expo modules, sets up the build mirror F-Droid compiles from, verifies the build locally, writes the fdroiddata recipe, and handles the GitLab side: the RFP, the merge request, the pipeline, Code Quality findings and the reviewer's questions.

It is distilled from two real submissions: Miroji (merged) and OmniMorse (closed, with the reasons recorded). Every rule in it came from one of those two, and the skill says which.

The twelve steps

  1. Survey the project
  2. Audit what F-Droid would reject
  3. Build the F-Droid variant
  4. Patch what cannot be removed
  5. Set up the build mirror
  6. Verify locally
  7. Put a test build on a real phone
  8. Write the recipe
  9. Submit on GitLab
  10. Get the pipeline green
  11. Go through review
  12. After it is published

Install

Any agent that reads the Agent Skills format

npx skills add RogerioDoCarmo/react-native-fdroid-publish

Claude Code, as a plugin

/plugin marketplace add RogerioDoCarmo/react-native-fdroid-publish
/plugin install react-native-fdroid-publish@rogeriodocarmo

Then ask your agent: “publish this app on F-Droid”, or “why did the F-Droid pipeline fail?”.

What it runs and sends

The skill is instructions and templates; your agent runs the commands it describes, in your project, with your approval. The GitLab script uses your own glab login and never reads, prints or stores a token. Every public text is shown to you before it is posted, and refused if it drops a line of F-Droid's current template or names another app store. Nothing is sent anywhere else.
